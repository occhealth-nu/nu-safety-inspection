# คู่มือผู้ดูแล (ผู้ดูแลระบบ / ผู้ประสานงานส่วนกลาง / ผู้ดูแลคณะ-หน่วยงาน)

## บทบาทและขอบเขต

| บทบาท | ทำอะไรได้ | ขอบเขต |
|---|---|---|
| ผู้ดูแลระบบมหาวิทยาลัย | หน่วยงาน, ผู้ใช้ทุกบทบาท, ภาพลักษณ์, ข้อมูลกลางทั้งหมด | ทั้งมหาวิทยาลัย |
| ผู้ประสานงานความปลอดภัยส่วนกลาง | แผนตรวจ, แบบตรวจกลาง, ติดตาม, มอบหมาย, ตรวจยืนยัน | ทั้งมหาวิทยาลัย |
| ผู้ดูแลคณะ/หน่วยงาน | จุดตรวจ, อาคาร, แผน, มอบหมายงาน, ผู้ใช้ในหน่วยงาน, แบบตรวจเฉพาะหน่วยงาน | หน่วยงานตน + หน่วยงานย่อย |

## 1. เตรียมข้อมูลพื้นฐาน (ครั้งแรก)

1. **ตั้งค่าระบบ › หน่วยงาน** — เพิ่มคณะ/กอง/ศูนย์ ใต้มหาวิทยาลัย (เฉพาะผู้ดูแลระบบ)
2. **ตั้งค่าระบบ › อาคาร ชั้น และห้อง** — เพิ่มอาคาร (ระบุจำนวนชั้นเพื่อสร้างชั้นอัตโนมัติ) แล้วเพิ่มห้อง/พื้นที่
3. **ตั้งค่าระบบ › ผู้ใช้และสิทธิ์** — สร้างบัญชี กำหนดบทบาท “ที่หน่วยงานใด”
   - ผู้ตรวจที่ตรวจหลายหน่วยงาน: เพิ่มบทบาทผู้ตรวจให้แต่ละหน่วยงาน
   - ช่าง/ผู้รับผิดชอบแก้ไข: บทบาท “ผู้รับผิดชอบแก้ไข” (มอบหมายข้ามหน่วยงานได้)
   - ระงับบัญชีแทนการลบ เพื่อรักษาประวัติ
4. **ตั้งค่าระบบ › แบบตรวจ** — ตรวจสอบแบบตรวจตัวอย่าง (ทุกฉบับเป็น *ร่างสำหรับผู้เชี่ยวชาญตรวจรับรอง*)

## 2. แบบตรวจและเวอร์ชัน

- เวอร์ชันที่ **เผยแพร่แล้วแก้ไขไม่ได้** → กด “สร้างเวอร์ชันใหม่เพื่อแก้ไข” ระบบคัดลอกรายการล่าสุดให้
- แต่ละข้อกำหนด: หัวข้อ, คำอธิบาย/เกณฑ์, วิธีตรวจ, ระดับความสำคัญ, อนุญาต “ไม่เกี่ยวข้อง”, บังคับแนบภาพเมื่อไม่ผ่าน
- **อ้างอิงกฎหมาย/มาตรฐาน**: ต้องระบุแหล่ง ฉบับ และวันที่ตรวจสอบครบทุกช่อง การยกเลิกสถานะ “ร่าง” ต้องระบุผู้เชี่ยวชาญที่รับรอง (ระบบบังคับ)
- กด “เผยแพร่” → การตรวจใหม่ใช้เวอร์ชันนี้; ผลตรวจเดิมยังแสดงเกณฑ์ของเวอร์ชันที่ใช้ในวันตรวจ

## 3. ทะเบียนจุดตรวจและ QR Code

1. **ทะเบียนจุดตรวจ › เพิ่มจุดตรวจ** — รหัส (อ่านได้ด้วยตา), ประเภท, หน่วยงาน, อาคาร/ชั้น/ห้อง, ผู้รับผิดชอบ, รุ่น, S/N, วันติดตั้ง/หมดอายุ, รอบตรวจ, สถานะ
2. สถานะ: ใช้งานอยู่ / หยุดใช้งาน / ย้าย / จำหน่าย (ตรวจได้เฉพาะ “ใช้งานอยู่”; ไม่มีการลบ)
3. **พิมพ์ QR**: รายชิ้นจากหน้ารายละเอียด หรือเลือกหลายรายการในทะเบียน → “พิมพ์ QR ที่เลือก” → พิมพ์ A4 (ปิดหัว/ท้ายกระดาษ) เลือกป้ายเล็ก/ใหญ่ได้
4. QR มีเพียงลิงก์รหัสอ้างอิงถาวร — ผู้สแกนต้องเข้าสู่ระบบและมีสิทธิ์จึงเห็นรายละเอียด; ป้ายเสียพิมพ์ใหม่ได้ด้วยรหัสเดิม
5. ตัวกรอง “ใกล้หมดอายุ/หมดอายุ (60 วัน)” ใช้ติดตามถังดับเพลิงหมดอายุ

## 4. แผนและงานตรวจ

1. **แผนและงานตรวจ › จัดการแผนการตรวจ** — ชื่อแผน, หน่วยงาน (รวมหน่วยงานย่อย), อาคาร/ประเภท (ไม่ระบุ = ทั้งหมด), แบบตรวจ, รอบ (รายวัน…รายปี/กำหนดเอง), วันเริ่ม-สิ้นสุด, ต้องตรวจภายในกี่วัน, ผู้ตรวจตั้งต้น
2. บันทึกแล้วระบบสร้างงานตรวจถึงสิ้นปีให้ทุกอุปกรณ์ที่ตรงเงื่อนไข; เพิ่มอุปกรณ์ใหม่ภายหลัง กด “สร้างงานถึงสิ้นปี” อีกครั้ง (ไม่สร้างซ้ำ)
3. หน้า **งานตรวจ**: เลือกหลายงาน → “มอบหมาย” ผู้ตรวจ (ผู้ตรวจได้รับแจ้งเตือนเมื่องานถึงรอบใน 7 วัน)

## 5. ติดตามแก้ไข

1. ข้อบกพร่องใหม่แจ้งเตือนผู้ดูแลหน่วยงาน (เร่งด่วน → แจ้งผู้ประสานงานส่วนกลางด้วย)
2. เปิดรายการ → “มอบหมายผู้รับผิดชอบแก้ไข”: ผู้รับผิดชอบ, กำหนดแล้วเสร็จ, มาตรการเบื้องต้น
3. หากต้องให้กองอาคารสถานที่ดำเนินการ: “ส่งใบงาน” → ออกเลขที่ใบงาน → เปิดใบงานเพื่อพิมพ์/บันทึก PDF
   > **ยังไม่ได้เชื่อมต่อ API ระบบภายนอก** — ต้องส่งเอกสารด้วยตนเอง สถานะใบงานแสดง “ยังไม่เชื่อมต่อระบบภายนอก”
4. แท็บ “เกินกำหนด” / “เร่งด่วน” / “เกิดซ้ำ” ใช้ติดตามประจำสัปดาห์

## 6. การแจ้งเตือน

**ตั้งค่าระบบ › การแจ้งเตือน** — เตือนล่วงหน้า N วัน, ยกระดับเมื่อเกินกำหนด N วัน, ผู้รับการยกระดับ (บทบาท), เปิด/ปิดอีเมลและประเภทการแจ้ง — ตั้งค่าเฉพาะหน่วยงานได้ (แทนค่าตั้งต้น)

## 7. รายงานและ Dashboard

- Dashboard: ตัวกรองหน่วยงาน/อาคาร/หมวด/ผู้รับผิดชอบ/ช่วงเวลา — คลิก KPI หรือช่องในตารางรายปีเพื่อดูรายการต้นทาง; นิยามสูตรแสดงใต้ KPI ทุกตัว (ดู `docs/KPI_DEFINITIONS.md`)
- รายงาน: ผลตรวจรายครั้ง, สรุปรายเดือน, งานค้าง, ทะเบียน/ประวัติอุปกรณ์, ผลการแก้ไข — Excel หรือ PDF (ผ่านหน้าพิมพ์ของเบราว์เซอร์) แสดงปี พ.ศ.

## 8. ประวัติการใช้งาน

**ตั้งค่าระบบ › ประวัติการใช้งาน** — ทุกการเพิ่ม/แก้ไข/ลบในตารางสำคัญถูกบันทึก (ผู้ทำ เวลา ฟิลด์ที่เปลี่ยน) แก้ไขหรือลบไม่ได้

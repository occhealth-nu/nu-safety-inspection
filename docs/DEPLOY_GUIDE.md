# คู่มือติดตั้งขึ้นใช้งานจริง (สำหรับผู้ไม่มีพื้นฐานด้านโปรแกรม)

คู่มือนี้ใช้บริการออนไลน์ 3 แห่ง ทำผ่านหน้าเว็บทั้งหมด **ไม่ต้องพิมพ์คำสั่งในเครื่อง**

| บริการ | ใช้ทำอะไร | เปรียบเทียบง่าย ๆ |
|---|---|---|
| **Supabase** | ฐานข้อมูล, ระบบเข้าสู่ระบบ, ที่เก็บรูปภาพ | “ตู้เก็บเอกสาร” ของระบบ |
| **GitHub** | เก็บไฟล์โปรแกรม (source code) | “โกดังเก็บไฟล์โปรแกรม” |
| **Vercel** | นำโปรแกรมขึ้นเว็บ ได้ลิงก์ https ให้ทุกคนเปิดใช้ | “หน้าร้าน” ที่ผู้ใช้เข้ามาใช้งาน |

เวลาที่ใช้: ประมาณ 1–2 ชั่วโมง · ค่าใช้จ่ายช่วงทดลอง: ฟรี (ดูข้อ 9 ก่อนใช้งานจริงทั้งมหาวิทยาลัย)

สิ่งที่ต้องเตรียม: คอมพิวเตอร์ + อีเมล + ไฟล์ `nu-safety-inspection.zip` (แตกไฟล์ไว้ในเครื่อง)

ไฟล์ที่ใช้ในคู่มือนี้อยู่ในโฟลเดอร์ `deploy/` ของโปรเจกต์:

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `01_install_database.sql` | สร้างฐานข้อมูลทั้งหมด (ครั้งเดียว) |
| `02_starter_data.sql` | ข้อมูลตั้งต้น: มหาวิทยาลัย + แบบตรวจ 8 หมวด + ประเภทอุปกรณ์ (ครั้งเดียว) |
| `03_demo_data_optional.sql` | (ไม่บังคับ) ข้อมูลตัวอย่างสำหรับทดลอง — **อย่าใช้กับระบบจริง** |
| `04_make_first_admin.sql` | ตั้งผู้ดูแลระบบคนแรก |

> 💡 เปิดไฟล์ `.sql` ด้วย Notepad (Windows) หรือ TextEdit (Mac) ได้ — คลิกขวา → Open with

## ขั้นที่ 1 — สร้างฐานข้อมูลที่ Supabase

### 1.1 สมัครและสร้างโปรเจกต์
1. ไปที่ **https://supabase.com** → กด **Start your project** → สมัคร (แนะนำ “Continue with GitHub” ถ้ามีบัญชี GitHub แล้ว หรือสมัคร GitHub ก่อนที่ https://github.com/signup)
2. กด **New project**
   - **Name:** `nu-safety`
   - **Database Password:** กด **Generate a password** แล้ว **คัดลอกเก็บไว้ในที่ปลอดภัย**
   - **Region:** เลือก **Southeast Asia (Singapore)** (ใกล้ไทยที่สุด)
3. กด **Create new project** → รอประมาณ 2 นาทีจนหน้าจอพร้อม

### 1.2 ติดตั้งฐานข้อมูล (คัดลอก–วาง)
1. เมนูซ้าย → **SQL Editor** → กด **+ New query**
2. เปิดไฟล์ `deploy/01_install_database.sql` ด้วย Notepad → กด **Ctrl+A** (เลือกทั้งหมด) → **Ctrl+C** (คัดลอก)
3. กลับไปที่ Supabase คลิกในช่องเขียน → **Ctrl+V** (วาง) → กดปุ่ม **Run** (มุมขวาล่าง)
4. ต้องเห็นข้อความ **“Success. No rows returned”**
   - ถ้ามีหน้าต่างเตือนเรื่อง “destructive operation” / “RLS” ให้กด **Run this query** ยืนยัน
5. กด **+ New query** อีกครั้ง → ทำแบบเดียวกันกับไฟล์ **`02_starter_data.sql`**
6. (ไม่บังคับ — ถ้าอยากเห็นตัวอย่างข้อมูลก่อนใช้จริง) ทำแบบเดียวกันกับ `03_demo_data_optional.sql`

ตรวจสอบ: เมนูซ้าย **Table Editor** ต้องเห็นตาราง เช่น `assets`, `findings`, `organizations` · เมนู **Storage** ต้องเห็น bucket `attachments` และ `branding`

> ⚠️ รันแต่ละไฟล์ **ครั้งเดียว** ถ้ารันซ้ำจะขึ้นข้อความ “already exists” — ไม่เป็นอันตราย ไม่ต้องทำอะไรเพิ่ม

### 1.3 ปิดการสมัครสมาชิกเอง (ให้ผู้ดูแลเป็นผู้สร้างบัญชีเท่านั้น)
เมนูซ้าย **Authentication** → **Sign In / Providers** (หรือ **Providers**) → ปิดสวิตช์ **Allow new users to sign up** → **Save**
(ตรวจว่า **Email** ยังเปิดอยู่)

### 1.4 สร้างผู้ดูแลระบบคนแรก
1. **Authentication** → **Users** → **Add user** → **Create new user**
   - ใส่อีเมลของคุณและตั้งรหัสผ่าน (อย่างน้อย 10 ตัวอักษร)
   - ติ๊ก **Auto Confirm User** → **Create user**
2. **SQL Editor** → **+ New query** → วางเนื้อหาไฟล์ `04_make_first_admin.sql`
3. แก้ 2 บรรทัดที่เขียนว่า `แก้ตรงนี้` — ใส่อีเมลที่เพิ่งสร้าง และชื่อที่ต้องการแสดง (เก็บเครื่องหมาย `'` ไว้)
4. กด **Run** → ต้องเห็นข้อความ “ตั้ง … เป็นผู้ดูแลระบบมหาวิทยาลัยเรียบร้อย”

### 1.5 คัดลอกค่าที่ต้องใช้ (เก็บไว้ใน Notepad ชั่วคราว)
เมนูซ้ายล่าง ⚙️ **Project Settings** → **API Keys** (บางรุ่นชื่อ **API**) และ **Data API**:

| ชื่อที่จะใช้ | หาได้ที่ | ตัวอย่างหน้าตา |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL (หน้า Data API หรือปุ่ม **Connect** ด้านบน) | `https://abcdxyz.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | **anon public** key (แท็บ *Legacy API Keys*) หรือ **Publishable key** | ข้อความยาว `eyJ…` หรือ `sb_publishable_…` |
| `SUPABASE_SERVICE_ROLE_KEY` | **service_role** key (แท็บ *Legacy API Keys*, กด Reveal) หรือ **Secret key** | `eyJ…` หรือ `sb_secret_…` |

> 🔒 **service_role / Secret key เป็นความลับระดับสูงสุด** (ใช้แก้ข้อมูลได้ทั้งหมด) ห้ามส่งทางแชท อีเมล หรือใส่ในไฟล์ที่เผยแพร่ — ใช้เฉพาะในขั้นที่ 3 เท่านั้น

## ขั้นที่ 3 — นำระบบขึ้นเว็บด้วย Vercel

1. ไปที่ **https://vercel.com/signup** → เลือก **Continue with GitHub** (ใช้บัญชีเดียวกับขั้นที่ 2)
2. กด **Add New… → Project** → ในรายการ repository กด **Import** ที่ `nu-safety-inspection`
   (ถ้าไม่เห็น ให้กด **Adjust GitHub App Permissions** แล้วอนุญาต repository นี้)
3. **Framework Preset** ต้องขึ้นว่า **Next.js** (ไม่ต้องแก้ส่วนอื่น)
4. เปิดหัวข้อ **Environment Variables** แล้วเพิ่มทีละรายการ (ช่องซ้าย = Key, ช่องขวา = Value):

| Key (พิมพ์ให้ตรงทุกตัวอักษร) | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ค่าจากข้อ 1.5 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ค่าจากข้อ 1.5 |
| `SUPABASE_SERVICE_ROLE_KEY` | ค่าจากข้อ 1.5 (ความลับ) |
| `CRON_SECRET` | ข้อความสุ่มยาว ≥ 32 ตัวอักษร (เช่น สร้างจาก https://1password.com/password-generator แบบ Random 40 ตัว ไม่มีสัญลักษณ์) |
| `NEXT_PUBLIC_APP_URL` | ใส่ชั่วคราว `https://nu-safety-inspection.vercel.app` (จะแก้ในข้อ 3.6) |
| `NEXT_PUBLIC_SSO_PROVIDER` | (ใส่ภายหลังเมื่อตั้งค่า Google เสร็จ — ขั้นที่ 3.8) `google` |

5. กด **Deploy** → รอ 2–4 นาที → ขึ้น 🎉 **Congratulations** → กด **Continue to Dashboard**
6. **ตรวจที่อยู่เว็บจริง:** ในหน้า Project จะเห็น **Domains** เช่น `nu-safety-inspection-xxxx.vercel.app`
   - ถ้า **ไม่ตรง** กับค่าที่ใส่ใน `NEXT_PUBLIC_APP_URL`: ไปที่ **Settings → Environment Variables** → แก้ `NEXT_PUBLIC_APP_URL` เป็น `https://ที่อยู่จริง` (ไม่มี / ท้าย) → **Save** → แท็บ **Deployments** → กด **⋯** ที่รายการบนสุด → **Redeploy**
   - ⚠️ ค่านี้ถูกพิมพ์ลงใน QR Code — **ต้องถูกต้องก่อนพิมพ์ป้าย QR** ถ้าเปลี่ยนโดเมนภายหลังต้องพิมพ์ QR ใหม่ทั้งหมด

### 3.7 บอก Supabase ว่าเว็บของเราอยู่ที่ไหน
Supabase → **Authentication → URL Configuration**
- **Site URL:** `https://ที่อยู่เว็บของคุณ.vercel.app`
- **Redirect URLs** → **Add URL:** `https://ที่อยู่เว็บของคุณ.vercel.app/auth/callback` → **Save**

## ขั้นที่ 3.8 — (แนะนำ) ให้บุคลากรเข้าด้วยบัญชี Google @nu.ac.th

ทำตาม **`docs/GOOGLE_LOGIN.md`** (ใช้เวลาประมาณ 20 นาที ต้องมีบัญชี @nu.ac.th ที่สร้างโปรเจกต์ใน Google Cloud ได้ หรือขอให้ฝ่ายไอทีทำส่วนที่ 1) — สรุป:

2. Supabase: เปิด Provider **Google** ใส่ Client ID/Secret
3. Vercel: เพิ่ม `NEXT_PUBLIC_SSO_PROVIDER` = `google` → Redeploy
4. ทำหน้าเว็บกลางบน Google Sites ที่มีปุ่มลิงก์เข้าระบบ และตั้งให้เห็นเฉพาะ nu.ac.th

2. มุมซ้ายล่าง **บัญชีของฉัน / เปลี่ยนรหัสผ่าน** — เปลี่ยนรหัสผ่านถ้าต้องการ

## ขั้นที่ 5 — ตั้งค่าเริ่มใช้งาน (ทำในระบบ)

ทำตามลำดับ (รายละเอียดใน `docs/MANUAL_ADMIN.md`):
1. **ตั้งค่าระบบ › ภาพลักษณ์ระบบ** — อัปโหลดตรามหาวิทยาลัยทางการ (ระบบไม่สร้างตราเอง)
2. **ตั้งค่าระบบ › หน่วยงาน** — เพิ่มคณะ/กอง/ศูนย์
3. **ตั้งค่าระบบ › อาคาร ชั้น และห้อง**
4. **ตั้งค่าระบบ › ผู้ใช้และสิทธิ์** — ลงทะเบียนอีเมล @nu.ac.th ของผู้ประสานงาน ผู้ดูแลคณะ ผู้ตรวจ ช่าง ผู้ตรวจยืนยัน ผู้บริหาร พร้อมบทบาท
   - ถ้าเปิดใช้ Google แล้ว: **เว้นช่องรหัสผ่านว่าง** ผู้ใช้เข้าด้วยปุ่ม Google ได้ทันที
   - ถ้ายังไม่เปิด Google: ตั้งรหัสผ่านชั่วคราว แจ้งผู้ใช้อย่างปลอดภัย ให้เปลี่ยนเองที่ “บัญชีของฉัน”
5. **ตั้งค่าระบบ › แบบตรวจ** — ให้ผู้เชี่ยวชาญทบทวน (ทุกแบบเป็น *ร่างสำหรับผู้เชี่ยวชาญตรวจรับรอง*)
6. **ทะเบียนจุดตรวจ › เพิ่มจุดตรวจ** → **พิมพ์ QR**
7. **แผนและงานตรวจ › จัดการแผนการตรวจ** → สร้างแผน (ระบบสร้างงานให้ทั้งปี)

ถ้าติดตั้งข้อมูลตัวอย่าง (ไฟล์ 03) แล้วจะเริ่มใช้งานจริง แนะนำ **สร้างโปรเจกต์ Supabase ใหม่** แล้วติดตั้งเฉพาะไฟล์ 01, 02, 04

## ขั้นที่ 6 — การแจ้งเตือนอัตโนมัติ

- ไฟล์ `vercel.json` ตั้งให้ Vercel เรียกงานแจ้งเตือน **วันละครั้ง เวลา 08:00 น.** (เวลาไทย) โดยอัตโนมัติ (ใช้ค่า `CRON_SECRET` ที่ตั้งไว้)
- ตรวจได้ที่ Vercel → Project → **Settings → Cron Jobs**
- การแจ้งเตือน **ในระบบ** (ไอคอนกระดิ่ง) ทำงานทันทีโดยไม่ต้องตั้งค่าเพิ่ม
- **อีเมล** ยังไม่ส่งจนกว่าจะตั้งค่า SMTP: ขอข้อมูลจากหน่วยงานไอที แล้วเพิ่ม Environment Variables `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` ใน Vercel → Redeploy

## ขั้นที่ 8 — แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| Vercel Deploy ไม่ผ่าน ขึ้น error เกี่ยวกับ `NEXT_PUBLIC_SUPABASE_URL` | ยังไม่ได้ใส่ Environment Variables หรือพิมพ์ชื่อ Key ผิด → แก้แล้ว Redeploy |
| เข้าสู่ระบบแล้วขึ้น “อีเมลหรือรหัสผ่านไม่ถูกต้อง” | ตรวจรหัสผ่าน / ผู้ใช้ต้องติ๊ก *Auto Confirm User* ตอนสร้าง (ถ้าลืม: Authentication → Users → คลิกผู้ใช้ → Confirm) |
| เข้าได้แต่ขึ้น “บัญชีของคุณยังไม่ได้รับบทบาท” | ยังไม่ได้รัน `04_make_first_admin.sql` หรือพิมพ์อีเมลในไฟล์ไม่ตรง |
| SQL ขึ้น “relation … does not exist” | รันไฟล์ผิดลำดับ → ต้องรัน 01 ก่อน 02 |
| สแกน QR แล้วกล้องไม่เปิด | ต้องเปิดผ่าน https และอนุญาตกล้องในเบราว์เซอร์; หรือพิมพ์รหัสจุดตรวจใต้ QR แทน |
| QR พาไปเว็บผิดที่อยู่ | `NEXT_PUBLIC_APP_URL` ไม่ถูกต้อง → แก้ + Redeploy แล้วพิมพ์ QR ใหม่ |
| เว็บช้าหรือเข้าไม่ได้หลังไม่ใช้ 1 สัปดาห์ | Supabase แบบฟรีหยุดโปรเจกต์อัตโนมัติเมื่อไม่มีการใช้งาน → เข้า Supabase กด **Restore project** (ใช้จริงควรใช้แผนเสียเงิน ดูข้อ 9) |
| อัปโหลดรูปไม่ได้ | ไฟล์ต้องเป็น JPG/PNG/WebP/PDF ไม่เกิน 10 MB; ตรวจว่ามี bucket `attachments` ใน Storage |

## ขั้นที่ 9 — ก่อนใช้งานจริงทั้งมหาวิทยาลัย (ควรปรึกษาหน่วยงานไอที)

- **แผนบริการ:** Supabase แบบฟรีหยุดโปรเจกต์เมื่อไม่ใช้งาน 1 สัปดาห์และไม่มีสำรองข้อมูลอัตโนมัติ → แนะนำ **Supabase Pro** · Vercel แบบ Hobby (ฟรี) กำหนดให้ใช้ส่วนตัว/ไม่ใช่เชิงองค์กร → งานของมหาวิทยาลัยควรใช้ **Vercel Pro** (ตรวจราคาปัจจุบันบนเว็บผู้ให้บริการ)
- **ทางเลือก:** ให้หน่วยงานไอทีติดตั้งบนเซิร์ฟเวอร์ของมหาวิทยาลัยเอง (Supabase แบบ self-host + Node.js) — ดู `docs/INSTALL.md`
- **ข้อมูลส่วนบุคคล (PDPA):** ข้อมูลเก็บที่สิงคโปร์ตาม Region ที่เลือก — ควรให้ฝ่ายกฎหมาย/DPO พิจารณา และกำหนดระยะเวลาเก็บรูปภาพ
- **ความปลอดภัย:** เปิด MFA ให้บัญชี Supabase/Vercel/GitHub ของผู้ดูแล, จำกัดผู้ที่เข้าถึง service_role key
- **SSO บัญชีมหาวิทยาลัย / API ระบบแจ้งซ่อม / อีเมล:** ยังไม่เชื่อมต่อ ต้องได้ข้อมูลจากหน่วยงานที่เกี่ยวข้อง (ดู `docs/TEST_REPORT.md`)

# คู่มือจัดการข้อมูลผ่าน Google Sheets (Apps Script) — NU Safety Inspection

ใช้ Google Sheets เป็นที่กรอกและแก้ข้อมูลหลักของระบบ แล้วกดเมนูเพื่อส่งข้อมูลเข้าระบบ ไม่ต้องคัดลอกคำสั่ง SQL เอง

* ข้อมูลที่ส่งได้: หน่วยงาน, อาคารและชั้น, ห้องและพื้นที่, จุดตรวจ, แผนการตรวจ, ผู้ใช้งาน
* ผลของแต่ละแถวจะขึ้นในคอลัมน์ **สถานะการส่ง** เป็น ✅ สำเร็จ หรือ ❌ พร้อมเหตุผลภาษาไทย
* ดึงรายงานกลับลงชีตได้ (สรุปรายอาคาร, ข้อบกพร่องค้าง, ผู้ใช้, ทะเบียนจุดตรวจ) และตั้งให้ดึงอัตโนมัติทุกเช้าได้

ใน Supabase SQL Editor ยังต้องรันไฟล์**ครั้งเดียวตอนติดตั้ง** (ส่วนที่ 1) ได้แก่ สร้างฐานข้อมูล ตั้งผู้ดูแลระบบ และสร้างรหัสนำเข้า หลังจากนั้นจัดการข้อมูลผ่านชีตได้ทั้งหมด

## ส่วนที่ 1 — เตรียมฐานข้อมูลใน Supabase (ทำครั้งเดียว)

วิธีรันไฟล์ .sql ทุกครั้ง

1. เข้า Supabase แล้วเปิด **SQL Editor**
2. กด **+ New query**
3. เปิดไฟล์ด้วย Notepad แล้วกด **Ctrl+A** และ **Ctrl+C**
4. กลับไปที่ Supabase แล้วกด **Ctrl+V** จากนั้นกด **Run**
5. ถ้ามีหน้าต่างเตือน ให้กด **Run this query**

> ตรวจก่อนว่าเปิดโปรเจกต์ถูกอัน: รหัสโปรเจกต์ในหน้า https://nu-safety-inspection.vercel.app/setup-check ต้องตรงกับแถบที่อยู่ของ Supabase (`supabase.com/dashboard/project/รหัส`)

### ทางเลือก ก — ติดตั้งใหม่ทั้งหมด (แนะนำ ล้างข้อมูลเก่าและ Demo)

| ขั้น | ไฟล์ | ผลที่ต้องเห็น |
|---|---|---|
| 1 | `1_RESET_delete_all_data.sql` | แก้บรรทัดที่ 15 จาก `'ไม่ลบ'` เป็น `'ลบทั้งหมด'` ก่อน Run แล้วต้องได้ `0 \| 0 \| false` |
| 2 | `2_install_database.sql` | Success. No rows returned |
| 3 | `3_starter_data.sql` | Success. No rows returned |
| 4 | `4_first_admin.sql` | แก้อีเมล @nu.ac.th และชื่อก่อน Run แล้วต้องได้ "ลงทะเบียนล่วงหน้าแล้ว … system_admin" |
| 5 | `5_create_import_key.sql` | ได้รหัสขึ้นต้นด้วย **nuimp_** ยาว 54 ตัวอักษร |

| 1 | `upgrade_existing_system.sql` | ตารางสุดท้ายมีแถว "รวมทั้งหมด" = 204 |

ถ้าขั้นที่ 1 ขึ้น error เรื่อง `building_safety_overview` หรือ `address` แปลว่าระบบเดิมยังไม่เคยอัปเกรด ให้ใช้ทางเลือก ก แทน

* ห้ามส่งรหัสทางแชตหรืออีเมล

## ส่วนที่ 2 — สร้าง Google Sheet จากแม่แบบ

1. เปิด https://drive.google.com ด้วยบัญชี Google ของผู้ดูแลระบบ
2. กด **+ ใหม่ → อัปโหลดไฟล์** แล้วเลือก `NU-Safety-Sheets-Template.xlsx`
3. ดับเบิลคลิกไฟล์ที่อัปโหลด แล้วกด **เปิดด้วย Google ชีต** ที่ด้านบน
4. เมนู **ไฟล์ → บันทึกเป็น Google ชีต** (สำคัญ: Apps Script ทำงานกับไฟล์ .xlsx โดยตรงไม่ได้)
5. ตั้งชื่อไฟล์ใหม่ เช่น **NU Safety — ข้อมูลหลัก**

ไฟล์ .xlsx ตัวเดิมใน Drive ลบได้

## ส่วนที่ 3 — ติดตั้ง Apps Script

1. ในชีต ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**
2. หน้าต่างใหม่จะเปิดขึ้นพร้อมไฟล์ `Code.gs` ให้ลบโค้ดเดิมทั้งหมด (`function myFunction() {…}`)
3. เปิดไฟล์ `Code.gs` จากชุดนี้ด้วย Notepad แล้วกด **Ctrl+A**, **Ctrl+C** และกลับไปวางด้วย **Ctrl+V**
4. คลิกชื่อ "โปรเจ็กต์ที่ไม่มีชื่อ" มุมซ้ายบน แล้วตั้งชื่อ **NU Safety**
5. กดไอคอน **💾 บันทึก** (หรือ Ctrl+S)
6. ปิดแท็บ Apps Script แล้วกลับไปที่ชีตและกด **F5** (รีเฟรช)
7. รอประมาณ 5–10 วินาที จะเห็นเมนู **NU Safety** ที่แถบเมนูด้านบน ถัดจาก "ความช่วยเหลือ"

### อนุญาตสิทธิ์ครั้งแรก (ทำครั้งเดียว)

ครั้งแรกที่กดคำสั่งในเมนู NU Safety Google จะถามสิทธิ์

1. กด **ดำเนินการต่อ (Continue)** แล้วเลือกบัญชีของคุณ
2. ถ้าขึ้น **"Google ยังไม่ได้ยืนยันแอปนี้"** ให้กด **ขั้นสูง (Advanced)** แล้วกด **ไปที่ NU Safety (ไม่ปลอดภัย)**
    * ข้อความนี้ขึ้นกับสคริปต์ทุกตัวที่เขียนเอง เพราะเป็นสคริปต์ของคุณเองในชีตของคุณ จึงไม่มีบริษัทใดไปขอรับรองไว้
3. กด **อนุญาต (Allow)**

สิทธิ์ที่ขอ

* อ่านและแก้ชีตนี้
* เชื่อมต่อบริการภายนอก ซึ่งในที่นี้คือ Supabase ของระบบ
* ตั้งเวลาทำงานอัตโนมัติ ใช้สำหรับดึงรายงานทุกเช้า

> ถ้าขึ้น "แอปนี้ถูกบล็อก" แปลว่าผู้ดูแล Google Workspace ของมหาวิทยาลัยปิดสคริปต์ที่ยังไม่ได้รับรองไว้ ให้ติดต่อฝ่าย IT เพื่อขออนุญาต หรือทำชีตด้วยบัญชี Google ที่มีสิทธิ์

## ส่วนที่ 4 — ตั้งค่าการเชื่อมต่อ

เมนู **NU Safety → 🔌 ตั้งค่าการเชื่อมต่อ** จะถาม 3 ค่า

| ลำดับ | ใส่อะไร | หาได้ที่ |
|---|---|---|
| 1/3 | **Project URL** เช่น `https://abcdxyz.supabase.co` | Supabase → ปุ่ม **Connect** ด้านบน หรือ Project Settings → Data API |
| 2/3 | **Publishable key** (`sb_publishable_…`) หรือ anon public key | Supabase → Project Settings → **API Keys** — ⚠️ **ห้ามใช้ Secret key** (ระบบจะปฏิเสธ) |
| 3/3 | **รหัสนำเข้า** `nuimp_…` | ผลจากส่วนที่ 1 |

ถ้าถูกต้องจะขึ้น **✅ เชื่อมต่อสำเร็จ** พร้อมจำนวนหน่วยงาน อาคาร และจุดตรวจในระบบ

* ค่าทั้ง 3 เก็บอยู่ในส่วนตั้งค่าซ่อนของสคริปต์ (Script Properties) ไม่แสดงในชีต
* คนที่ไม่มีสิทธิ์แก้ชีตจะไม่เห็นค่าเหล่านี้

## ส่วนที่ 5 — ส่งข้อมูลเข้าระบบครั้งแรก

1. แท็บ **ผู้ใช้งาน**: กรอกอีเมล @nu.ac.th ชื่อ และตำแหน่งของคนที่มีแล้ว ส่วนแถวที่ยังไม่มีคนให้ปล่อยว่างไว้
2. เมนู **NU Safety → ⬆️ ส่งทุกแท็บ (เฉพาะแถวใหม่/ที่แก้ไข)**
3. รอประมาณ 10–60 วินาที แล้วจะขึ้นสรุป เช่น

    ```
    ✅ หน่วยงาน: สำเร็จ 43 · ไม่สำเร็จ 0
    ✅ อาคารและชั้น: สำเร็จ 204 · ไม่สำเร็จ 0
    ✅ ห้องและพื้นที่: สำเร็จ 36 · ไม่สำเร็จ 0
    ✅ จุดตรวจ: สำเร็จ 60 · ไม่สำเร็จ 0
    ✅ แผนการตรวจ: สำเร็จ 5 · ไม่สำเร็จ 0
    ✅ ผู้ใช้งาน: สำเร็จ … · ไม่สำเร็จ 0
    ```

4. ถ้ามี ❌ ให้เปิดแท็บนั้นแล้วดูเหตุผลในคอลัมน์ **สถานะการส่ง** แก้ข้อมูลในแถวนั้น แล้วส่งอีกครั้ง
    * ระบบส่งเฉพาะแถวที่ยังไม่สำเร็จหรือที่แก้ไข
5. รันไฟล์ `6_check_database.sql` ใน Supabase ต้องได้ ✅ ครบ 8 ข้อ
    * หรือเปิด https://nu-safety-inspection.vercel.app/setup-check แล้วดู 3 บรรทัดล่าง
6. แจ้งผู้ใช้ให้เข้าเว็บด้วย **บัญชี Google ของมหาวิทยาลัย** ระบบจะให้สิทธิ์ตามที่กรอกในชีตทันที

## ส่วนที่ 6 — การใช้งานประจำ

| ต้องการ | ทำอย่างไร |
|---|---|
| เพิ่มผู้ใช้ | เพิ่มแถวในแท็บ ผู้ใช้งาน (เลือกสังกัดและบทบาทจากดรอปดาวน์) → เมนู **ส่งแท็บนี้** |
| ให้ผู้ใช้คนเดียวมีหลายบทบาท | เพิ่มหลายแถวโดยใช้อีเมลเดิม แต่ละแถวเป็นบทบาทหรือหน่วยงานต่างกัน |
| ให้สิทธิ์ต่างจากสังกัด | ใส่คอลัมน์ "หน่วยงานที่ได้รับสิทธิ์ (unit)" เช่น สังกัดคณะ แต่เป็นผู้ประสานงานของกองอาคารสถานที่ |
| เติมจำนวนชั้น | แก้ช่อง **จำนวนชั้น** ในแท็บ อาคารและชั้น ระบบจะขึ้น ✏️ รอส่ง → **ส่งแท็บนี้** → ได้ข้อความ "(+N ชั้น)" |
| แก้ชื่ออาคาร หน่วยงานเจ้าของ เลขอาคาร หรือประเภท | แก้ในแถว → ส่งแท็บนี้ |
| เพิ่มอาคาร ห้อง หรือจุดตรวจใหม่ | เพิ่มแถวต่อท้ายในแท็บนั้น → ส่งแท็บนี้ |
| เพิ่มแผนการตรวจของหน่วยงานอื่น | เพิ่มแถวในแท็บ แผนการตรวจ → ส่ง (ระบบสร้างงานตรวจให้อัตโนมัติ) |
| ดูภาพรวม | เมนู **⬇️ ดึงรายงาน** → ได้แท็บ รายงาน-อาคาร / รายงาน-ข้อบกพร่อง / รายงาน-ผู้ใช้ / รายงาน-จุดตรวจ |
| ให้รายงานอัปเดตเองทุกเช้า | เมนู **⏰ ดึงรายงานอัตโนมัติทุกเช้า (07:00)** |

ข้อควรรู้

* **ห้ามเปลี่ยนชื่อแท็บหรือหัวคอลัมน์แถวที่ 1** เพราะสคริปต์ใช้ชื่อหัวคอลัมน์หาข้อมูล (สลับลำดับคอลัมน์ได้)
* **การลบแถวในชีตไม่ได้ลบข้อมูลในระบบ** เป็นการป้องกันลบผิด ถ้าต้องการปิดใช้งานอาคาร จุดตรวจ หรือระงับผู้ใช้ ให้ทำในเว็บ
* แท็บ **รายงาน-…** ถูกเขียนทับทุกครั้งที่ดึง อย่าพิมพ์ข้อมูลอื่นไว้ในแท็บเหล่านี้
* งานที่ทำในเว็บต่อได้เลย: ปักพิกัดอาคาร อัปโหลดผังชั้น ปักหมุดจุดตรวจ พิมพ์ QR

## ส่วนที่ 7 — ความปลอดภัย

* แชร์ชีตนี้**เฉพาะผู้ดูแลระบบ** ซึ่งต้องมีสิทธิ์**แก้ไข**จึงจะใช้เมนูได้ ไม่ควรแชร์แบบ "ทุกคนที่มีลิงก์"
* ไม่ต้องใส่ Secret key ของ Supabase ในชีตหรือสคริปต์ และ**ห้ามใส่**
* เมื่อผู้ดูแลเปลี่ยนคน หรือสงสัยว่ารหัสรั่ว ให้ทำดังนี้
    1. ใน Supabase SQL Editor รัน `select app.revoke_import_keys();`
    2. รันไฟล์ `5_create_import_key.sql` เพื่อสร้างรหัสใหม่
    3. ในชีต ไปที่เมนู NU Safety → ตั้งค่าการเชื่อมต่อ แล้วใส่รหัสใหม่
* ดูการใช้รหัสได้ด้วยคำสั่ง `select name, key_hint, last_used_at, use_count, revoked_at from app.import_keys;`
* ทุกครั้งที่ส่งข้อมูลจากชีต ระบบบันทึกไว้ในประวัติการใช้งาน (audit log) ของระบบ

# อัปเกรด: ระบบตรวจสอบความปลอดภัยอาคาร (ระบุตำแหน่งในพื้นที่ตรวจ)

เอกสารนี้อธิบาย **สิ่งที่เพิ่มเข้ามา** และ **วิธีอัปเกรดระบบที่ใช้งานอยู่ทีละขั้นตอน** สำหรับผู้ดูแลที่ไม่มีพื้นฐานด้านโปรแกรม
ข้อมูลเดิมทั้งหมด (ผู้ใช้ จุดตรวจ ผลตรวจ ข้อบกพร่อง รูปภาพ) **ไม่หายและไม่ถูกแก้ไข**

---

## 1. สิ่งที่เพิ่มเข้ามา

### 1.1 สโคปพื้นที่จากใหญ่ไปเล็ก

```
อาคาร                   เช่น EN1                               (เพิ่ม: พิกัด GPS, ที่อยู่)
└─ ชั้น                  เช่น ชั้น 1                              (เพิ่ม: ภาพผังชั้น)
   └─ ห้อง/พื้นที่        เช่น ทางเดินหลัก                         (เดิม)
      └─ จุดตรวจ/อุปกรณ์  เช่น ถังดับเพลิง FE-EN1-101              (เพิ่ม: หมุดบนผังชั้น, พิกัด GPS)
         └─ ข้อบกพร่อง    เช่น NC-2569-00083                     (เพิ่ม: หมุดตำแหน่งที่พบจริง)
```

* **ความเป็นเจ้าของ/สิทธิ์ยังเป็นไปตาม “หน่วยงาน” เหมือนเดิม** (คณะ/กอง) — อาคารแต่ละหลังมีหน่วยงานเจ้าของ
* **ไม่มีระดับวิทยาเขต/โซน** (ยกเลิกแล้ว) — ถ้าเคยรันสคริปต์ฉบับก่อนที่มีวิทยาเขต/โซน ให้รัน `deploy/05` ฉบับนี้ซ้ำ ระบบลบออกให้โดยไม่กระทบข้อมูลอื่น

### 1.2 การระบุตำแหน่ง

| ระดับ | ข้อมูลตำแหน่ง | ใช้ทำอะไร |
|---|---|---|
| อาคาร | พิกัด GPS (ละติจูด, ลองจิจูด) | ลิงก์ “แผนที่/นำทาง” (Google Maps) · ใช้เทียบระยะกับตำแหน่งผู้ตรวจ |
| ชั้น | ภาพผังชั้น (JPG/PNG/WebP ≤ 10 MB) | พื้นหลังสำหรับหมุดจุดตรวจและข้อบกพร่อง |
| จุดตรวจ | หมุดบนผังชั้น (X, Y เป็น %) และพิกัด GPS (เฉพาะจุดภายนอกอาคาร) | ผู้ตรวจหาจุดเจอ · เห็นสถานะทั้งชั้นในภาพเดียว |
| ข้อบกพร่อง | หมุดตำแหน่งที่พบจริง + คำอธิบาย | ช่างไปถึงจุดที่ต้องแก้ได้ตรง |
| ผลตรวจ | พิกัดผู้ตรวจ **ครั้งเดียวขณะกดส่งผล** + ระยะห่างจากจุดตรวจ/อาคาร | ยืนยันว่าตรวจหน้างานจริง (“อยู่ในพื้นที่” / “นอกรัศมี”) |

### 1.3 หน้าจอใหม่/ที่ปรับปรุง

| หน้า | สิ่งที่เพิ่ม |
|---|---|
| **อาคารและพื้นที่** (เมนูใหม่) | การ์ดสถานะความปลอดภัยรายอาคาร จัดกลุ่มตามหน่วยงานเจ้าของ |
| **อาคาร › ผังชั้น** | แท็บชั้น · ผังพร้อมหมุดสีตามสถานะ · รายการจุดตรวจแยกตามห้อง · ข้อบกพร่องค้างของชั้น |
| ตั้งค่าระบบ › **สถานที่และผังชั้น** | พิกัดอาคาร · อัปโหลดผังชั้น · ตั้งค่าการยืนยันตำแหน่งผู้ตรวจ |
| เพิ่ม/แก้ไขจุดตรวจ | แตะบนผังเพื่อปักหมุด · พิกัด GPS (จุดภายนอก) |
| รายละเอียดจุดตรวจ / หน้าสแกน QR | การ์ด “ตำแหน่ง” พร้อมผังชั้นและลิงก์นำทาง |
| รายละเอียดข้อบกพร่อง | การ์ด “ตำแหน่งข้อบกพร่อง” ปักหมุดจุดที่พบจริงได้ |
| แบบฟอร์มตรวจ / ผลตรวจ | ขอพิกัดขณะส่งผล · แสดงสถานะ “อยู่ในพื้นที่ตรวจ” หรือ “นอกรัศมี” |
| รายงาน | รายงานใหม่ **สรุปความปลอดภัยรายอาคาร** (Excel/PDF) |

### 1.4 ความหมายของสีหมุด (ใช้สัญลักษณ์คู่กับสีเสมอ)

| หมุด | ความหมาย |
|---|---|
| 🔴 `!` | เร่งด่วน: มีข้อบกพร่องระดับสูง/วิกฤตค้าง หรือมีงานตรวจเกินกำหนด |
| 🟠 `•` | มีข้อบกพร่องค้าง (ไม่เร่งด่วน) |
| 🟢 `✓` | ปกติ |
| ⚪ `–` | ไม่ได้ใช้งาน |
| 🟣 `✕` (สี่เหลี่ยม) | ตำแหน่งข้อบกพร่องที่ปักหมุดแยกจากจุดตรวจ |

## 2. วิธีอัปเกรดระบบที่ใช้งานอยู่ (ทำครั้งเดียว ประมาณ 15 นาที)

> ทำตามลำดับ **ขั้นที่ 1 → 4** · ระหว่างอัปเกรดผู้ใช้ยังใช้งานได้ (หน้าใหม่จะใช้ได้หลังขั้นที่ 3 เสร็จ)

### ขั้นที่ 1 — สำรองข้อมูลก่อน (แนะนำ)
1. เข้าระบบ → เมนู **รายงาน** → ช่วงเวลา “ปีงบประมาณ” → ดาวน์โหลด **Excel ทุกฉบับ** เก็บไว้ในไดรฟ์ของหน่วยงาน
2. (ถ้าใช้ Supabase แผน Pro) Supabase → **Database → Backups** ตรวจว่ามีสำรองของวันนี้

> สคริปต์อัปเกรด **เพิ่ม** ตาราง/คอลัมน์เท่านั้น ไม่ลบข้อมูลเดิม แต่การสำรองไว้ก่อนเป็นแนวปฏิบัติที่ดีเสมอ

### ขั้นที่ 2 — อัปเกรดฐานข้อมูล (Supabase)
1. เปิดไฟล์ `deploy/05_upgrade_building_locations.sql` ใน GitHub
   (github.com → repository `nu-safety-inspection` → โฟลเดอร์ `deploy` → คลิกชื่อไฟล์ → ปุ่ม **Copy raw file** ไอคอนรูปสี่เหลี่ยมซ้อนมุมขวาบน)
2. เข้า [supabase.com/dashboard](https://supabase.com/dashboard) → เลือกโปรเจกต์ → เมนูซ้าย **SQL Editor** → **+ New query**
3. วาง (Ctrl+V) ทั้งไฟล์ → กด **Run** (หรือ Ctrl+Enter)
4. ต้องเห็นข้อความ **Success. No rows returned** ด้านล่าง
   * ถ้าขึ้นกล่องเตือน “potentially destructive operation” ให้กด **Run this query** (สคริปต์มีคำสั่ง `drop view` เพื่อสร้างมุมมองข้อมูลใหม่ — ไม่ได้ลบข้อมูล)
   * ถ้าหลุดกลางทางหรือ error ให้ **รันใหม่ทั้งไฟล์** ได้อย่างปลอดภัย (รันซ้ำได้)
5. ตรวจผล: New query → วางคำสั่งนี้ → Run
   ```sql
   select (select count(*) from public.buildings where latitude is not null) as buildings_with_gps,
          (select count(*) from public.assets where plan_x is not null) as pinned_assets,
          (select count(*) from storage.buckets where id = 'floor-plans') as floor_plan_bucket;
   ```
   ควรได้ `floor_plan_bucket = 1` (สองค่าแรกเป็น 0 ได้ถ้ายังไม่ได้ตั้งค่าตำแหน่ง)

> ติดตั้งระบบใหม่ทั้งหมด (ฐานข้อมูลว่าง): ใช้ `deploy/01_install_database.sql` ซึ่งรวมการอัปเกรดนี้แล้ว — **ไม่ต้อง** รัน 05

### ขั้นที่ 3 — อัปเดตเว็บไซต์ (Vercel)
โค้ดใหม่อยู่บน GitHub สาขา `main` แล้ว Vercel จะ deploy ให้อัตโนมัติ
1. Vercel → โปรเจกต์ → แท็บ **Deployments** → รายการบนสุดต้องเป็น **Ready** (สีเขียว)
2. ถ้ารายการบนสุดยังเป็นของเก่า: กด **⋯** → **Redeploy** → **Redeploy**
3. ไม่ต้องเพิ่ม Environment Variable ใหม่

### ขั้นที่ 4 — ตรวจว่าใช้งานได้
1. เปิด `https://<โดเมนของระบบ>/setup-check` → ทุกแถวเป็นเครื่องหมายถูก
2. เข้าสู่ระบบ → เมนูซ้ายต้องมี **อาคารและพื้นที่** → เปิดแล้วเห็นการ์ดอาคาร

## 3. ตั้งค่าใช้งานครั้งแรก (ผู้ดูแลระบบ/ผู้ดูแลคณะ)

| ลำดับ | ทำอะไร | ใครทำ | ที่ไหน |
|---|---|---|---|
| 1 | เลือกอาคาร → ระบุ **พิกัดอาคาร** และที่อยู่ | ผู้ดูแลคณะ (อาคารของตน) | ตั้งค่าระบบ › สถานที่และผังชั้น › 1 (คลิกอาคาร) › การ์ด “ตำแหน่งอาคาร” |
| 2 | **อัปโหลดผังชั้น** ทุกชั้นที่มีจุดตรวจ | ผู้ดูแลคณะ | › 2 › อัปโหลดผังชั้น |
| 3 | **ปักหมุดจุดตรวจ** ทุกจุด | ผู้ดูแลคณะ | ทะเบียนจุดตรวจ › จุดตรวจ › แก้ไข › ตำแหน่งบนผังชั้น |
| 4 | ตั้งรัศมีการยืนยันตำแหน่งผู้ตรวจ (ค่าเริ่มต้น 300 ม.) | ผู้ดูแลระบบ | › การยืนยันตำแหน่งผู้ตรวจขณะส่งผล |

### 3.1 การหาพิกัด GPS ของอาคาร (2 วิธี)
* **ยืนที่หน้าอาคาร** → เปิดหน้าแก้ไขอาคารบนมือถือ → กด **ใช้ตำแหน่งปัจจุบัน** → อนุญาตตำแหน่ง → **บันทึก**
* **จาก Google Maps บนคอมพิวเตอร์** → คลิกขวาที่หลังคาอาคาร → คลิกตัวเลขพิกัดบรรทัดแรก (คัดลอกแล้ว) → วางในช่อง “ละติจูด” แล้วแยกตัวเลขหลังเครื่องหมายจุลภาคไปช่อง “ลองจิจูด”

### 3.2 การเตรียมภาพผังชั้น
* ใช้แบบแปลนจากกองอาคารสถานที่ หรือผังหนีไฟที่ติดอยู่ในอาคาร (ถ่ายภาพให้ตรง ไม่เอียง)
* ไฟล์ PDF/CAD: เปิดแล้ว **บันทึกเป็นภาพ PNG/JPG** (หรือจับภาพหน้าจอ) ความกว้าง 1,500–3,000 px
* **หมุนให้ทิศเหนืออยู่ด้านบน** เหมือนกันทุกชั้น และครอปให้เหลือเฉพาะตัวอาคาร
* **ตัดข้อมูลที่ไม่ควรเผยแพร่** (เช่น ตำแหน่งตู้เซฟ ระบบรักษาความปลอดภัย) — ผังชั้นเปิดดูได้เฉพาะผู้มีสิทธิ์ในอาคารนั้น แต่ควรระวังไว้ก่อน
* เปลี่ยนผังภายหลังได้ หมุดเดิมยังอยู่ที่ตำแหน่ง % เดิม จึงควรใช้ภาพที่ครอปและสัดส่วนเหมือนเดิม

### 3.3 ความเป็นส่วนตัวของตำแหน่งผู้ตรวจ (PDPA)
* ระบบขอพิกัด **ครั้งเดียวขณะกดส่งผลตรวจ** ไม่ติดตามตำแหน่งตลอดเวลา และไม่บันทึกเมื่อเปิดหน้าอื่น
* วัตถุประสงค์: ยืนยันว่าการตรวจเกิดขึ้นที่หน้างานจริง · ผู้ตรวจปฏิเสธได้ (ระบบบันทึก “ไม่อนุญาต” และยังส่งผลได้)
* ผู้ที่เห็นพิกัด = ผู้มีสิทธิ์ดูผลตรวจนั้นเท่านั้น (ผู้ตรวจ ผู้ดูแลหน่วยงาน ผู้ตรวจยืนยัน ผู้บริหารในขอบเขต)
* ปิดการบันทึกได้ที่ ตั้งค่าระบบ › สถานที่และผังชั้น › “บันทึกพิกัดผู้ตรวจขณะส่งผล” (เฉพาะผู้ดูแลระบบ)
* ควรแจ้งผู้ตรวจล่วงหน้าและระบุในประกาศความเป็นส่วนตัวของหน่วยงาน

### 4.2 ฐานข้อมูล
* หัวข้อ 0 ของ migration ลบตาราง/คอลัมน์ `campuses`, `zones`, `buildings.campus_id/zone_id` ที่อาจมีจากฉบับก่อน (`if exists`)
* คอลัมน์ใหม่: `buildings(latitude, longitude, address)` · `floors(plan_path, plan_updated_at)` ·
  `assets(plan_x, plan_y, latitude, longitude)` · `findings(plan_x, plan_y, location_note)` ·
  `inspections(geo_lat, geo_lng, geo_accuracy_m, geo_distance_m, geo_status, geo_captured_at)` · `app_settings(geo_capture_enabled, geo_radius_m)`
* Trigger: `findings_default_pin` (ข้อบกพร่องใหม่ใช้หมุดของจุดตรวจ)
* RPC ใหม่ (security definer ตรวจสิทธิ์ในฟังก์ชัน):
  `set_floor_plan(floor, path)` · `set_finding_pin(finding, x, y, note)` · `record_inspection_location(inspection, lat, lng, accuracy, status)`
* RPC อ่าน (security invoker ผ่าน RLS): `building_safety_overview(from, to, org)` (จัดกลุ่มตามหน่วยงานเจ้าของ)
* ฟังก์ชันแดชบอร์ดทั้ง 4 เพิ่มพารามิเตอร์ `p_floor` (มีค่าเริ่มต้น การเรียกแบบเดิมยังใช้ได้)
* Views `v_assets / v_inspection_tasks / v_findings / v_inspections` เพิ่มคอลัมน์สโคป (`floor_id, location_id, floor_name, …`) ต่อท้าย
* Storage bucket **private** `floor-plans` path `floor/{floor_id}/{uuid}.{ext}` — อ่าน: `app.can_view_building` (มีบทบาทในหน่วยงานเจ้าของอาคาร หรือเห็นจุดตรวจในอาคาร) · เขียน/ลบ: `app.can_manage_building`

### 4.4 ย้อนกลับ (ถ้าจำเป็น)
โค้ดเวอร์ชันใหม่ต้องใช้ฐานข้อมูลที่อัปเกรดแล้ว แต่ฐานข้อมูลที่อัปเกรดแล้ว **ยังใช้กับโค้ดเวอร์ชันเดิมได้** (คอลัมน์ใหม่ไม่บังคับ และฟังก์ชันแดชบอร์ดรับพารามิเตอร์เดิมได้)
หากต้องย้อนเว็บไซต์: Vercel → Deployments → เลือกรายการก่อนหน้า → ⋯ → **Promote to Production** (ไม่ต้องแก้ฐานข้อมูล)

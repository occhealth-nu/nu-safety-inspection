# เปิดใช้ “เข้าสู่ระบบด้วยบัญชี Google ของมหาวิทยาลัย” (@nu.ac.th) และหน้าเว็บกลางบน Google Sites

เป้าหมาย: **ให้เข้าระบบได้เฉพาะบุคลากรที่มีบัญชี @nu.ac.th** ไม่ต้องจำรหัสผ่านเพิ่ม และมีหน้าเว็บกลางบน Google Sites สำหรับเปิดระบบ/คู่มือ

> ข้อมูลยังเก็บที่ Supabase เหมือนเดิม — Google ทำหน้าที่ “ยืนยันตัวตน” เท่านั้น

## ระบบกันบุคคลภายนอกอย่างไร (4 ชั้น)

| ชั้น | ทำงานอย่างไร |
|---|---|
| 1. Google OAuth แบบ **Internal** | ตั้งค่าใน Google Cloud ให้เฉพาะผู้ใช้ในองค์กร nu.ac.th ลงชื่อเข้าใช้ได้ (Google ปฏิเสธบัญชีภายนอกตั้งแต่ต้น) |
| 2. ฐานข้อมูล | trigger ปฏิเสธการสร้างบัญชีจาก Google ที่อีเมลไม่ใช่โดเมนที่อนุญาต, องค์กร Google (hd) ไม่ตรง หรืออีเมลยังไม่ยืนยัน |
| 3. หน้า `/auth/callback` | ตรวจโดเมนซ้ำฝั่งเซิร์ฟเวอร์ ไม่ผ่าน → ออกจากระบบทันที |
| 4. สิทธิ์ (RLS) | ผู้ใช้ใหม่ **ไม่เห็นข้อมูลใดเลย** จนกว่าผู้ดูแลกำหนดหน่วยงานและบทบาท |

## ส่วนที่ 1 — ตั้งค่า Google Cloud (ต้องใช้บัญชี @nu.ac.th ที่ได้รับสิทธิ์จากผู้ดูแล Google Workspace ของมหาวิทยาลัย)

> ถ้าคุณไม่มีสิทธิ์สร้างโปรเจกต์ใน Google Cloud ขององค์กร ให้ส่งส่วนที่ 1 นี้ให้ฝ่ายไอทีทำ แล้วขอ **Client ID** และ **Client Secret** กลับมา

1. เปิด **https://console.cloud.google.com** → ลงชื่อด้วยบัญชี @nu.ac.th
   (ถ้ามีแถบ “Start your Free Trial with $300” ให้กด **Dismiss** — ไม่ต้องเปิด Free Trial หรือใส่บัตรเครดิต การสร้าง OAuth client ไม่มีค่าใช้จ่าย)
2. แถบบนสุด กดเลือกโปรเจกต์ → **New Project** → ชื่อ `nu-safety-inspection` → Organization: **nu.ac.th** → **Create**
3. เมนู ☰ → **APIs & Services → OAuth consent screen** (บางรุ่นชื่อ **Google Auth Platform → Branding/Audience**)
   - กด **Get started** / **Configure**
   - App name: `NU Safety Inspection` · User support email: อีเมลของคุณ
   - **Audience / User type: เลือก `Internal`** ← สำคัญที่สุด (เฉพาะผู้ใช้ในองค์กรเท่านั้น)
   - Contact email: อีเมลของคุณ → **Create / Save**
4. เมนู **Clients** (หรือ **APIs & Services → Credentials**) → **+ Create client / Create credentials → OAuth client ID**
   - Application type: **Web application** · Name: `NU Safety Supabase`
   - **Authorized JavaScript origins** (ไม่บังคับ — ถ้าเผลอกด Add URI จนช่องเป็นสีแดง ให้ใส่ที่อยู่เว็บระบบ เช่น `https://nu-safety-inspection-xxxx.vercel.app` **ไม่มี / ต่อท้าย และไม่มี path** หรือกดไอคอนถังขยะลบช่องว่างทิ้ง)
   - **Authorized redirect URIs** → **+ Add URI** แล้ววาง:
     `https://<รหัสโปรเจกต์>.supabase.co/auth/v1/callback`
     (คัดลอกค่าที่ถูกต้องได้จาก Supabase ขั้นที่ 2.2 ด้านล่าง — ช่อง “Callback URL (for OAuth)”)
   - **Create** → จะได้ **Client ID** และ **Client Secret** → คัดลอกเก็บไว้ (Client Secret เป็นความลับ)

## ส่วนที่ 2 — ตั้งค่า Supabase

1. Supabase → **Authentication → Sign In / Providers** (หรือ **Providers**) → เลือก **Google**
2. เปิดสวิตช์ **Enable Sign in with Google**
   - **Client IDs:** วาง Client ID
   - **Client Secret (for OAuth):** วาง Client Secret
   - คัดลอก **Callback URL (for OAuth)** ไปใช้ในส่วนที่ 1 ข้อ 4 (ถ้ายังไม่ได้ใส่)
   - **Save**
3. ตรวจ **Authentication → URL Configuration** ว่ามี Redirect URL `https://<เว็บของคุณ>/auth/callback` (ทำไว้แล้วตามคู่มือ Deploy ข้อ 3.7)
4. ตรวจว่า **Allow new users to sign up** — การเข้าด้วย Google ครั้งแรกถือเป็นการสร้างบัญชีใหม่:
   - **แนะนำ: เปิดไว้** (ปลอดภัยเพราะมีการกันโดเมน 4 ชั้นด้านบน และผู้ใช้ใหม่ไม่มีสิทธิ์ใดจนผู้ดูแลอนุมัติ)
   - ถ้าต้องการให้ **เฉพาะคนที่ผู้ดูแลลงทะเบียนล่วงหน้า** เท่านั้นเข้าได้: ปิดไว้ แล้วลงทะเบียนอีเมลทุกคนในระบบก่อน (ส่วนที่ 4)

## ส่วนที่ 3 — เปิดปุ่ม Google ในระบบ (Vercel)

1. Vercel → Project → **Settings → Environment Variables** → **Add**
   - Key: `NEXT_PUBLIC_SSO_PROVIDER` · Value: `google`
   - (ถ้าโดเมนไม่ใช่ nu.ac.th) Key: `NEXT_PUBLIC_SSO_DOMAIN` · Value: โดเมนของคุณ
2. **Deployments → ⋯ → Redeploy**
3. เปิดหน้าเข้าสู่ระบบ ต้องเห็นปุ่ม **“เข้าสู่ระบบด้วยบัญชี Google ของมหาวิทยาลัย (@nu.ac.th)”**
   (การเข้าด้วยอีเมล/รหัสผ่านยังใช้ได้ โดยพับไว้ใต้ปุ่ม — ใช้สำหรับผู้ดูแลกรณีฉุกเฉิน)
4. ระบบ › **ตั้งค่าระบบ › ภาพลักษณ์และการเข้าสู่ระบบ** → ช่อง **โดเมนอีเมลที่อนุญาต** ต้องเป็น `nu.ac.th` (ค่าเริ่มต้น)

## ส่วนที่ 4 — การให้สิทธิ์บุคลากร (เลือกได้ 2 แบบ)

**แบบ A: ลงทะเบียนล่วงหน้า (แนะนำ)** — ผู้ใช้ได้สิทธิ์ทันทีที่เข้าครั้งแรก
1. ตั้งค่าระบบ › **ผู้ใช้และสิทธิ์** → **เพิ่มผู้ใช้ใหม่**
2. ใส่ **อีเมล @nu.ac.th**, ชื่อ, หน่วยงาน, บทบาท — **เว้นช่องรหัสผ่านว่าง**
3. แจ้งผู้ใช้ให้เปิดระบบแล้วกด “เข้าสู่ระบบด้วยบัญชี Google ของมหาวิทยาลัย”

**แบบ B: ให้ผู้ใช้เข้ามาเองก่อน แล้วอนุมัติ**
1. ผู้ใช้กดปุ่ม Google → เข้าได้แต่เห็นข้อความ “ยังไม่ได้รับบทบาท… ระบบแจ้งผู้ดูแลส่วนกลางแล้ว”
2. ผู้ดูแลระบบ/ผู้ประสานงานส่วนกลางได้รับแจ้งเตือน 🔔 “ผู้ใช้ใหม่รอกำหนดสิทธิ์”
3. ตั้งค่าระบบ › ผู้ใช้และสิทธิ์ › แท็บ **รอกำหนดสิทธิ์** → **+ เพิ่มบทบาท** (เลือกบทบาท + หน่วยงาน) — ระบบตั้งหน่วยงานให้อัตโนมัติจากบทบาทแรก

**เมื่อบุคลากรลาออก/ย้ายงาน:** ตั้งค่าระบบ › ผู้ใช้และสิทธิ์ → **ระงับ** หรือถอนบทบาท (บัญชี Google ที่มหาวิทยาลัยปิดแล้วจะเข้าไม่ได้อยู่แล้ว)

## ส่วนที่ 5 — หน้าเว็บกลางบน Google Sites

Google Sites ใช้เป็น “ประตูทางเข้า” และที่รวมคู่มือ (ระบบตรวจทำงานบนเว็บของตัวเอง ฝังทั้งระบบไว้ใน Sites ไม่ได้ เพราะเบราว์เซอร์บล็อกการเข้าสู่ระบบภายในกรอบเว็บอื่นเพื่อความปลอดภัย)

1. เปิด **https://sites.google.com** ด้วยบัญชี @nu.ac.th → **+ Blank site**
2. ตั้งชื่อ เช่น “ระบบตรวจความปลอดภัย มหาวิทยาลัยนเรศวร”
3. แทรก → **Button** → ข้อความ `เข้าสู่ระบบตรวจความปลอดภัย` → ลิงก์ `https://<เว็บของคุณ>` (เปิดในแท็บใหม่)
4. เพิ่มเนื้อหาที่มีประโยชน์ เช่น
   - คู่มือ: อัปโหลด `docs/MANUAL_INSPECTOR.md` ฯลฯ เป็น Google Docs แล้วแทรกจาก **Drive**
   - ช่องทางติดต่อผู้ดูแล, ประกาศรอบตรวจ, วิดีโอสอนการสแกน QR
   - (ถ้าต้องการ) รายงานสรุปที่ส่งออกเป็น Excel → อัปโหลดเข้า Shared Drive → แทรกใน Sites
5. **Publish** → ในหน้าต่าง Publish ตั้ง **Who can view my site: เฉพาะผู้ใช้ใน nu.ac.th** → **Publish**

## แก้ปัญหา

| อาการ | วิธีแก้ |
|---|---|
| Google ขึ้น “Access blocked: … can only be used within its organization” | บัญชีที่ใช้ไม่ใช่ @nu.ac.th — ถูกต้องตามที่ตั้งใจ |
| Google ขึ้น `redirect_uri_mismatch` | Authorized redirect URI ใน Google Cloud ไม่ตรงกับ Callback URL ของ Supabase (ตรวจตัวอักษรทุกตัว รวม https และ /auth/v1/callback) |
| กลับมาที่ระบบแล้วขึ้น “ระบบนี้สำหรับบุคลากรเท่านั้น” | อีเมลไม่อยู่ในโดเมนที่อนุญาต — ตรวจช่องโดเมนในตั้งค่าระบบ |
| เข้าได้แต่ “ยังไม่ได้รับบทบาท” | ผู้ดูแลยังไม่กำหนดสิทธิ์ (ส่วนที่ 4) |
| ไม่เห็นปุ่ม Google | ยังไม่ได้ตั้ง `NEXT_PUBLIC_SSO_PROVIDER=google` หรือยังไม่ได้ Redeploy |
| ขึ้น “Unsupported provider” | ยังไม่ได้เปิด Google ใน Supabase (ส่วนที่ 2) |

## สถานะการทดสอบ

ทดสอบอัตโนมัติแล้ว: การกันโดเมนในฐานข้อมูล (บัญชี gmail.com, hd ไม่ตรง, อีเมลไม่ยืนยัน, ผู้ใช้ใหม่ไม่เห็นข้อมูล, แจ้งผู้ดูแล), ปุ่ม Google ส่งไปยัง Google พร้อม `hd=nu.ac.th` ผ่าน Supabase Auth จริง, ข้อความเมื่อถูกปฏิเสธ, การลงทะเบียนล่วงหน้าและปฏิเสธอีเมลนอกโดเมน
**ยังไม่ได้ทดสอบกับบัญชี Google Workspace จริงของมหาวิทยาลัย** — ต้องทดสอบหลังตั้งค่าส่วนที่ 1–3 (ลองทั้งบัญชี @nu.ac.th และบัญชี Gmail ส่วนตัว ซึ่งต้องเข้าไม่ได้)

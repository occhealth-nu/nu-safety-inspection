### E2E: วงจรครบตามข้อกำหนด
`สร้างจุดตรวจ → พิมพ์ QR → สร้างแผน/งาน (admin.spec)` และ `ตรวจ (มือถือ 390px) + แนบภาพ → พบปัญหา → มอบหมาย → รับงาน → ส่งโดยไม่มีภาพถูกปฏิเสธ → แนบภาพ → ส่งผล → ส่งกลับ → แนบภาพใหม่ → ส่งผล → ตรวจยืนยันปิดงาน → Dashboard/ตารางรายปี/Excel/PDF (flow.spec)` รวมถึงทุกหน้าโหลดได้สำหรับ 4 บทบาท (เวลาโหลด 60–700 ms)

ภาพหน้าจอจากการทดสอบ: `docs/screenshots/`

### ปัญหาที่พบและแก้ระหว่างทดสอบ
1. **ปุ่มค้าง “กำลังบันทึก”** เป็นครั้งคราว (≈1 ใน 6) หลัง Server Action ของ Next.js 15 — ข้อมูลบันทึกแล้วแต่ client router ยกเลิกการนำทางต่อ → เปลี่ยนคำสั่งทั้งหมดเป็น `/api/actions/{name}` (fetch + ยืนยันจาก Backend + โหลดหน้าใหม่พร้อมข้อความยืนยัน) ทดสอบซ้ำไม่พบอีก
2. **หน้าโหลดช้า 5–12 วินาทีสำหรับผู้ใช้ระดับหน่วยงาน** จาก RLS fallback ที่เรียกฟังก์ชันรายแถว → เขียน policy ใหม่แบบ inline + `(select …)` init-plan + index ใหม่ → เหลือ 20–200 ms
3. ข้อความ “กรอกไม่ครบ” ค้างหลังกรอกครบ และปุ่ม “ไม่เกี่ยวข้อง” ล้นบนจอ 390px → แก้แล้ว
4. **ช่องโหว่ด้านสิทธิ์ (แก้แล้ว):** เมื่องานตรวจหรือข้อบกพร่อง *ยังไม่มีผู้รับผิดชอบ* (ค่า NULL) เงื่อนไขตรวจสิทธิ์บางจุดใน RPC ประเมินเป็น NULL ทำให้ไม่ถูกปฏิเสธ — ผู้ตรวจต่างหน่วยงานเปิดร่างตรวจได้ และคนนอกอาจแนบไฟล์/ออกใบงาน/รายงานความคืบหน้าได้ พบจาก E2E → แก้ทุกจุดด้วย `coalesce(…, false)` และเพิ่มการทดสอบ 6 กรณี

## รายการที่ยังไม่พร้อมใช้งานจริง (ต้องดำเนินการก่อนเปิดใช้)

| เรื่อง | สถานะ | สิ่งที่ต้องทำ |
|---|---|---|
| เกณฑ์ในแบบตรวจ | ร่างสำหรับผู้เชี่ยวชาญตรวจรับรองทั้งหมด **ไม่ได้อ้างอิงกฎหมาย/มาตรฐาน** | ผู้เชี่ยวชาญทบทวน ระบุแหล่ง/ฉบับ/วันที่ตรวจสอบ แล้วเผยแพร่เวอร์ชันใหม่ |
| เข้าสู่ระบบด้วย Google @nu.ac.th | พัฒนาและทดสอบแล้วกับ Supabase Auth จริง (ปุ่ม → Google พร้อม hd, การกันโดเมนในฐานข้อมูล, ข้อความปฏิเสธ, ลงทะเบียนล่วงหน้า) **ยังไม่ได้ทดสอบกับบัญชี Google Workspace จริง** | ตั้งค่าตาม `docs/GOOGLE_LOGIN.md` แล้วทดสอบด้วยบัญชี @nu.ac.th และบัญชี Gmail ส่วนตัว (ต้องเข้าไม่ได้) |
| ระบบแจ้งซ่อมกองอาคารสถานที่ | **ยังไม่เชื่อม API** — ออกใบงานในระบบ + พิมพ์/PDF | ได้สเปก API แล้วเพิ่ม integration (มีช่อง `integration_status`, `external_ref` รองรับ) |
| อีเมลแจ้งเตือน | โค้ดส่งผ่าน SMTP พร้อม; **ยังไม่ได้ทดสอบกับ SMTP จริง** (ทดสอบเฉพาะกรณีไม่ตั้งค่า → skipped) | ตั้งค่า SMTP + Cron แล้วทดสอบ |
| Storage | E2E ใช้ storage emulator ที่บังคับ RLS เดียวกัน **ไม่ใช่ Supabase Storage จริง** | ทดสอบอัปโหลด/ลิงก์อายุจำกัดบนโปรเจกต์ Supabase จริง |
| ตรามหาวิทยาลัย | ไม่มีไฟล์ตรา (แสดงอักษร “NU”) | อัปโหลดตราทางการที่ได้รับอนุญาต |
| ออฟไลน์ | **ไม่รองรับส่งผลออฟไลน์** (มีเพียงเก็บร่างในเครื่อง + แจ้งเตือน) | หากจำเป็น ต้องพัฒนาคิวซิงก์ + IndexedDB เพิ่ม |
| PDF | ใช้หน้าพิมพ์ของเบราว์เซอร์ (ภาษาไทยถูกต้อง) ไม่มีการสร้าง PDF ฝั่งเซิร์ฟเวอร์ | หากต้องการไฟล์ PDF อัตโนมัติ (เช่น แนบอีเมล) ต้องเพิ่ม headless browser |
| การทดสอบโหลด/ปริมาณข้อมูลจริง | ทดสอบกับ ~50 อุปกรณ์, ~500 งาน/ปี | ทดสอบกับข้อมูลระดับมหาวิทยาลัย (หมื่นจุดตรวจ) และเพิ่ม pagination/materialized view ถ้าจำเป็น |
| ความปลอดภัยสารสนเทศ/PDPA | ออกแบบตาม least privilege แต่ยังไม่ผ่านการตรวจสอบอิสระ | Security review, นโยบายเก็บรักษาภาพ/ข้อมูลส่วนบุคคล, ประกาศความเป็นส่วนตัว |
| การเข้าถึง (Accessibility) | ใช้ข้อความ+ไอคอนคู่สี, label ฟอร์ม, ปุ่ม ≥ 44px | ยังไม่ได้ทดสอบกับโปรแกรมอ่านหน้าจอจริง |
| การลบไฟล์ใน Storage | ลบได้เฉพาะไฟล์ในร่าง/งานยังไม่ปิด; ไม่มีงานลบไฟล์กำพร้าอัตโนมัติ | เพิ่มงานทำความสะอาดตามรอบ |
